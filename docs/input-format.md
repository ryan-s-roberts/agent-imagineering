# Parameterized property-case input

All dataset-reading commands take `--input-dir` pointing **directly** at the
directory containing the numbered cases. There is no required repository parent
or `Property Management` wrapper and no special case-ID range of 001–050.

```text
input-dir/
  001/
    history.md
    index.md                  # optional; never model input
    attachments/
      inspection.pdf
  002/
    history.md
```

Case directories use three-digit IDs. `history.md` uses the upstream event format:

```markdown
## 2026-01-01 09:00:00 UTC — event 001

- **Channel:** Email
- **From:** Tenant
- **To:** Agency / system

Event body, optionally linking [an attachment](attachments/inspection.pdf).
```

Event IDs must be contiguous from 001. Prefix cutoffs are explicit event numbers.
Only events through the cutoff and attachments linked by those events enter the
model context. `index.md`, summary/outcome text outside the history and unlinked
attachments do not. The PDF parser and its limitations are unchanged. Input
symlinks are rejected and attachment paths cannot escape their case directory.

## New unseen data

The unseen directory is external; the vendored public copy is development material.
Freeze the ontology, decision prompt and rubric before inspecting unseen outcomes.
No development annotations are looked up by a new case's numeric ID.

For a prediction-only run where each supplied history is already the available
prefix, build an explicit end-of-history manifest:

```sh
uv run python -m property_eval.dataset \
  --input-dir /path/to/unseen-cases --split unseen --cutoff-policy end \
  --output runs/unseen-manifest.json

uv run python -m property_eval.attachment_extraction prepare \
  --input-dir /path/to/unseen-cases --manifest runs/unseen-manifest.json \
  --output runs/unseen-v1

uv run python -m property_eval.attachment_extraction run \
  --input-dir /path/to/unseen-cases --output runs/unseen-v1 \
  --env-file /path/to/.env
```

Preparation records `input-data.json` with a dataset fingerprint, case inventory
and file hashes. A manifest generated by `property_eval.dataset` pins this fingerprint.
Existing explicit-cutoff manifests are accepted, and their exact prefixes and
attachment context are hashed at preparation. The canonical `run.json` embeds the
input inventory; `index.html` and per-case answers render saved results.

If unseen histories include future evaluation episodes, use a separately supplied
manifest of authorized cutoffs instead of `end`. Reference annotation and historical
judging are separate operations. Without references, report prediction outputs and
prefix-supportedness—not historical accuracy. Never select unseen checkpoints by
reading their outcomes as part of the decision pipeline.

The end-of-history manifest command makes no model calls and reads no case indices
as evidence. Hashing an index file for dataset integrity does not expose its text
to the decision agent.
